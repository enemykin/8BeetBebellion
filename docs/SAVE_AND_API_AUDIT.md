# Предварительная проверка API и сохранений — 2026-10-01

Проверка выполнена для пользовательского расшифрованного iPhone IPA 1.4.5 и текущего локального touchHLE. Исполняемый файл прочитан непосредственно из ZIP в памяти; его содержимое и игровые ресурсы не сохранялись в отчёт и не добавлялись в Git. Список импортов сам по себе не доказывает, что игра вызовет каждый API в офлайн-кампании. Селекторы Objective-C могут вызываться динамически и не исчерпываются таблицей импортов.

## Кандидаты на следующие пробелы совместимости

В таблице неопределённых символов ARMv7 обнаружено 1394 записи, включая 162 ссылки на классы Objective-C. Сопоставление имён со строками в исходниках touchHLE даёт следующие **кандидаты**, а не подтверждённые причины падения:

| Область | Импорты, которых не найдено в исходниках touchHLE | Оценка |
| --- | --- | --- |
| Геометрия | `_CGRectIsEmpty` | Возможен при переходах интерфейса после уже исправленного `_CGRectContainsRect`. |
| Интерфейс и изображение | `_OBJC_CLASS_$_UITableViewCell`, `_UIImagePNGRepresentation` | Могут понадобиться в экранах персонажей и при работе с изображениями. |
| Core Graphics | `_CGContextAddRect`, `_CGContextBeginPath`, `_CGContextClosePath`, `_CGContextFillPath`, `_CGContextMoveToPoint`, `_CGContextStrokeRectWithWidth`, `_CGImageGetBitmapInfo` и другие функции рисования | Вероятны только в соответствующей ветви интерфейса. |
| Звук | `_AudioFileWritePackets`, `_AudioQueueNewInput` | Потребуются лишь если игра использует запись/ввод звука. |
| Foundation/Core Foundation | `_OBJC_CLASS_$_NSHTTPCookieStorage`, `_CFArrayRemoveAllValues`, `_CFStringCreateWithCharacters` | Возможны в сетевых и общих служебных путях. |

Кроме того, загрузчик уже сообщил о недоступных `/usr/lib/libicucore.A.dylib` и `CoreAudio.framework`, а также о неразрешённых `_CFCopyDescription` и ряде сетевых констант. Это отдельный риск, но его влияние на офлайн-кампанию не подтверждено. Многие прочие неопределённые символы относятся к самой игре или поставляемым с touchHLE библиотекам. Добавлять заглушки только по наличию импорта нельзя: неверная семантика может скрыть следующий сбой или испортить данные.

## Как игра сохраняет данные

touchHLE отображает гостевой `Documents` в локальный `vendor/touchHLE/touchHLE_sandbox/com.alife.linkinpark/Documents`. Найдены следующие постоянные файлы:

| Файл | Наблюдаемая роль |
| --- | --- |
| `Player.sqlite` | SQLite с таблицами `PlayerItem`, `PlayerMission`, `PlayerInternalData`, `Achievement` и др. Игра открывает базу и готовит запросы для предметов и заданий. |
| `Player.p` | Небольшой файл с собственной сигнатурой `GC_ENCRYPTOT`; формат и точный состав сохранённого состояния пока не установлены. В последнем запуске он не обновлялся. |
| `Player_optiondict` | Список настроек в plist, включая звук, вибрацию и обучение; обновлён в последнем запуске. |
| `Player_Tutorial` | 45 целочисленных состояний подсказок: `0` — ещё не показана, `1` — показана и ожидает завершения, `2` — завершена. При загрузке игра сама сбрасывает `1` в `0`, поэтому такие подсказки повторяются. |
| `localdefault`, `Player.apartment` | Дополнительные локальные данные; их семантика полностью не установлена. |
| `Library/Preferences/com.alife.linkinpark.plist` | Существует, но текущий словарь `NSUserDefaults` пуст. |

Локальная `Player.sqlite` проходит `PRAGMA quick_check` (`ok`). Сейчас в ней 18 записей предметов, одна запись `PlayerMission` с `mission_id=0`, `mission_state=0`, `finished=0` и одна запись `PlayerInternalData` (`GiftCounter`). Это подтверждает наличие постоянных данных, но не доказывает сохранение прогресса кампании. Содержимое пользовательских полей и игровых ресурсов в отчёт не включено.

## Обнаруженная ошибка записи миссии

В `reports/manual-run-2026-10-01_10-01-32-72838.log` четыре раза встречается `Update mission error: 14`. Непосредственно перед ошибкой SQLite запрашивает `TMPDIR`, затем пытается создать `./etilqs_*` в гостевом рабочем каталоге `/`; touchHLE отказывает, поскольку каталог только для чтения. Код 14 в SQLite — `SQLITE_CANTOPEN`. На основании этого наблюдения в начальные гостевые переменные окружения touchHLE добавлен `TMPDIR`, указывающий на уже существующую записываемую папку приложения `tmp`. Проверка каталога в SQLite запрашивает сочетание прав записи и поиска; `access()` в touchHLE до исправления не обрабатывал сочетания флагов. Добавлена проверка всех запрошенных битов с адресным тестом.

Последующие ручные запуски `reports/manual-run-2026-10-01_11-22-57-76588.log` и `reports/manual-run-2026-10-01_11-24-46-76808.log` используют гостевую `tmp` и больше не показывают `Update mission error: 14`. `PlayerMission.mission_state` в постоянной базе изменился с 0 на 2; по наблюдению пользователя следующий запуск сохранил изменённого персонажа и пропустил редактор. Файл `Player.p` обновился при штатном выходе. Таким образом, часть сохранения и восстановления работает. Для уверенного заключения о всей кампании нужно пройти этап задания и сравнить игровое состояние после полного перезапуска.

## Подсказки и плакаты

На 2026-10-01 в `Player_Tutorial` находились три состояния `1` (индексы 1, 7, 14), остальные уже показанные подсказки имели `2`. Дизассемблирование `TutorialManager loadState` подтвердило сброс каждого `1` в `0` при запуске. Адресная совместимость touchHLE для версии 1.4.5 перед загрузкой игры преобразует сохранённые `1` в `2`, сохраняя ещё не показанные `0`. Это отвечает требованию не повторять уже увиденные подсказки; полная ручная проверка после перезапуска ещё нужна.

`PlayerMission.mission_state=7` — этап задания, а не число собранных плакатов: `LPMission1 defacePoster:` проверяет именно значение 7 перед обновлением цели. Метод `defacedPosterCount` считает длину `defacedPosterList` (`std::vector<int>`); `ScenePoster` использует тот же список ID, чтобы определить, сорван ли конкретный плакат. При создании `LPMission1` список пуст. В текущей строке `PlayerMission` поле `mission_data` равно `NULL`, поэтому из него нельзя восстановить ID или счётчик. В существующих локальных файлах и логах ID ранее собранных плакатов не обнаружены.

Для версии 1.4.5 добавлено локальное сохранение списка ID в `Documents/8beet-poster-progress-v1`. touchHLE считывает список после создания `LPMission1` и восстанавливает его игровым методом `defacePoster:`; новые ID записываются при изменении списка. После исправления перезаписи временно пустым списком пользователь подтвердил, что число и состояние собранных плакатов сохраняются после выхода из игры. Уже потерянные до этого исправления ID восстановить из `mission_state=7` нельзя.

Первая реализация этой синхронизации оказалась неполной. В `reports/manual-run-2026-10-01_14-42-28-2945.log` были записаны 1 и 2 ID, а последующие запуски восстанавливали до 3 ID. Однако при загрузке следующей панели игра временно очищает вектор, и эмулятор записывал `Saved 0`, стирая файл. Это видно, например, в `reports/manual-run-2026-10-01_14-44-40-3478.log` (`Restored 3`, затем `Saved 0`). Исправление сохраняет объединение уже записанных и текущих ID, восстанавливает отсутствующие после смены панели и никогда не трактует временный пустой вектор как сброс задания. Проверка после перезапуска ожидается.
